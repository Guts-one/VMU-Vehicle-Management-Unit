Using the simulator

  1. Set the inputs. Adjust speed, engine RPM, power demand, and battery charge. Negative power demand represents braking.
  2. Apply a step. The controller evaluates one state transition. The instruments show the last applied inputs; edits remain pending until applied.
  3. Explore a preset or cycle. Presets reach an operating mode from standstill and record the transitions. Cycles start a fresh session and apply scripted inputs every 0.1 s. Pause and resume at any time.
  4. Inspect the results. Telemetry and the session log record the inputs and controller outputs. Export CSV saves up to the latest 1,200 samples. Clear data keeps the current mode; Reset restores the initial state.

The engine-speed dial is an input to the supervisor, not a calculated engine response. Motor, generator, and engine indicators show enable commands; they do not measure energy flow.

JavaScript inputs use the same fixed-point conversion and mode logic as the project's C comparison harness. See the verification evidence and limits.
